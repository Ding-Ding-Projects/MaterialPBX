# Contributing

Thank you for improving MaterialPBX. Keep changes narrow, explain user-visible behavior, use typed controls instead of raw configuration-only fields when values can be discovered, and never display sample data as a live PBX result.

Before proposing a change, update the affected feature article, roadmap, handoff, and changelog. Keep credentials, private data, build output, and installed dependencies out of Git. Commits use a concise English subject, a playful Hong Kong-style Cantonese counterpart in the body, and factual details in both languages.
